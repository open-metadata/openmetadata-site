## Changelog

OpenMetadata 1.13.7 is a maintenance release with improvements to connector ingestion, lineage, data quality, and pipeline observability.

### Connectors and lineage

- **Databricks ingestion missed jobs in large workspaces.** Job discovery follows pagination tokens until all pages are retrieved. [#33244](https://github.com/open-metadata/OpenMetadata/pull/33244)
- **Unity Catalog lineage missed dependencies.** Databricks lineage uses the source and target rows reported by Unity Catalog, with SQL-based lineage where available. [#33391](https://github.com/open-metadata/OpenMetadata/pull/33391)
- **PostgreSQL and Greenplum ingestion skipped materialized views.** Both connectors now include materialized views in metadata extraction. [#33426](https://github.com/open-metadata/OpenMetadata/pull/33426)
- **Source tags and schema definitions could be lost during ingestion.** Source tags are added alongside existing tags when metadata override is off. The stored schema definition is retained when a connector does not return one. [#33710](https://github.com/open-metadata/OpenMetadata/pull/33710) [#33992](https://github.com/open-metadata/OpenMetadata/pull/33992)

### Data quality and observability

- **Test case status could reflect an older run.** The status now follows the newest result. The test case table filter also includes column-level tests. [#34289](https://github.com/open-metadata/OpenMetadata/pull/34289) [#33570](https://github.com/open-metadata/OpenMetadata/pull/33570)
- **Pipeline observability could count one DAG more than once.** It now reports each DAG once using its newest run. [#33687](https://github.com/open-metadata/OpenMetadata/pull/33687)
