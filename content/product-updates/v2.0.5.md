## Changelog

OpenMetadata 2.0.5 is a maintenance release focused on connector and lineage reliability. It restores metadata affected by 2.0 ingestion regressions and protects user-managed metadata during bot ingestion. It also improves several user interface (UI) paths and updates Jackson dependencies for two security vulnerabilities.

### 🔌 Connectors and Ingestion

This release includes the following connector and ingestion fixes:

- **Redshift datashare databases on consumer clusters weren't ingested** [#34381](https://github.com/open-metadata/OpenMetadata/pull/34381): The connector now identifies non-local databases and reads their schemas and tables through Redshift's cross-database catalog views. It also reads their columns and descriptions.
- **Oracle foreign-key constraints disappeared when identifier casing differed** [#34415](https://github.com/open-metadata/OpenMetadata/pull/34415): Referred table names now keep the database's original casing, so OpenMetadata can resolve and ingest the constraints.
- **Mode report queries omitted columns, column lineage, and owners** [#34733](https://github.com/open-metadata/OpenMetadata/pull/34733): Mode ingestion now extracts query columns, builds column-level lineage, and assigns report creators as owners when their email matches an OpenMetadata user.

### 🔀 Lineage

This release includes the following lineage fixes:

- **Databricks dropped lineage through jobs when reads and writes appeared in separate records** [#34732](https://github.com/open-metadata/OpenMetadata/pull/34732): Databricks now preserves lineage when a job reads and writes tables in separate query-history records.
- **Entity-relationship diagrams reversed foreign-key cardinality** [#34812](https://github.com/open-metadata/OpenMetadata/pull/34812): The diagrams now show the correct one-to-many relationship for foreign keys after reindexing.

### 🛡️ Data Governance and Quality

This release includes the following governance and data quality fixes:

- **Upgrading from OpenMetadata 2.0 could remove ingestion-managed metadata** [#34836](https://github.com/open-metadata/OpenMetadata/pull/34836): The 2.0.5 migration restores affected descriptions, display names, and retention periods. It also restores table constraints and tags. Ingestion bots now preserve existing descriptions when a source provides an empty value.
- **Bot ingestion overwrote user-managed tags, owners, and retention periods** [#34792](https://github.com/open-metadata/OpenMetadata/pull/34792): Bot ingestion now preserves user-managed tags that aren't supplied by the source. It also keeps user-assigned owners and retention periods unless an explicit override reassigns the owners.

### 🎛️ UI

This release includes the following UI fixes:

- **The sign-in page loaded its decorative video before the application loaded** [#34801](https://github.com/open-metadata/OpenMetadata/pull/34801): The video now starts after the application loads and remains disabled for people who prefer reduced motion.
- **Long glossary term names were clipped in the picker** [#34887](https://github.com/open-metadata/OpenMetadata/pull/34887): Picker rows now fit the dropdown width and show the full term name in a tooltip when truncated.
- **Custom properties with one entity reference didn't render** [#34891](https://github.com/open-metadata/OpenMetadata/pull/34891): The UI now renders these custom properties when the application programming interface (API) returns one entity reference as an object instead of a list.

### 🔒 Security

**Jackson dependencies contained resource-exhaustion vulnerabilities** [#34004](https://github.com/open-metadata/OpenMetadata/pull/34004): OpenMetadata updates Jackson 2.x to 2.18.11 and Jackson 3.x to 3.1.7 to address CVE-2026-89425 and CVE-2026-91777.
