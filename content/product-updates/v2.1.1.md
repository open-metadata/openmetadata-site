## Changelog

OpenMetadata 2.1.1 is a maintenance release that improves single sign-on (SSO) and Security Assertion Markup Language (SAML) sign-in and keeps you on the page you opened after sign-in. It fixes glossary approval, Inbox task, and governance workflow issues. Glossary terms that are not Approved are now held as pending. It also improves dbt and MicroStrategy ingestion, alert status, pagination, and MySQL hard delete.

### 🔐 Authentication and SSO

This release includes the following SSO and authentication fixes:

- **SAML identity provider certificate handling was improved** [#38302](https://github.com/open-metadata/OpenMetadata/pull/38302), [#38318](https://github.com/open-metadata/OpenMetadata/pull/38318): SAML sign-in now keeps and validates the identity provider's certificates, and the server starts when a saved certificate has expired. The 2.1.1 upgrade rewrites a stored certificate as standard Privacy-Enhanced Mail (PEM) text.
- **A deep link opened while signed out was lost after sign-in** [#38578](https://github.com/open-metadata/OpenMetadata/pull/38578): You now land on the page you opened after you sign in.
- **Model Context Protocol (MCP) sign-in failed for some accounts** [#38557](https://github.com/open-metadata/OpenMetadata/pull/38557), [#38558](https://github.com/open-metadata/OpenMetadata/pull/38558): MCP sign-in now accepts the Google issuer when it has no scheme, and an account that is not allowed sees a 403 Access Denied page instead of a 500 error.
- **Custom property delete on the Profile page used a different permission** [#38430](https://github.com/open-metadata/OpenMetadata/pull/38430): The delete action now depends on the `EditAll` permission.

### 🛡️ Data Governance and Workflows

This release includes the following governance and workflow fixes:

- **Writes that applied a glossary term that was not Approved were rejected** [#38511](https://github.com/open-metadata/OpenMetadata/pull/38511): Such a write is now accepted, and the term is held as pending. It is hidden from reads and search until the term is approved, and then it is applied to each asset that holds it.
- **Suggestions on assets without an owner had no reviewer** [#38560](https://github.com/open-metadata/OpenMetadata/pull/38560): A suggestion task now goes to the service owners, then the domain owners, then the admins other than the requester. The 2.1.1 upgrade applies the same setting to the stored suggestion workflow.
- **Governance rules did not trigger for some entity reference changes** [#38514](https://github.com/open-metadata/OpenMetadata/pull/38514): Rules that check a change description now trigger when the new value is an entity reference that holds only an `id` and `type`.
- **Data Product bulk port changes could partly commit** [#38515](https://github.com/open-metadata/OpenMetadata/pull/38515): Adding or removing input and output ports in bulk now runs in one transaction, so a failure partway no longer saves part of the batch.
- **The 2.1.0 upgrade repair of context file names needed a stricter check** [#38513](https://github.com/open-metadata/OpenMetadata/pull/38513): The repair now checks the derived fully qualified name across all entity tables before it moves tags.
- **Certifications could be returned without an expiry date** [#38562](https://github.com/open-metadata/OpenMetadata/pull/38562): Every read now returns a certification with both dates.
- **The profiler stopped at a table it could not parse** [#38562](https://github.com/open-metadata/OpenMetadata/pull/38562): The profiler now skips a table it can't parse instead of dropping the rest of the page.

### ✅ Tasks and Inbox

This release includes the following task and Inbox fixes:

- **Glossaries with many pending proposals lost Approve and Reject** [#38425](https://github.com/open-metadata/OpenMetadata/pull/38425): The Terms tab now follows every page of open approval tasks. A glossary with more than 50 pending proposals now keeps Approve, Reject, and the correct **Proposed by** author on every term.
- **The incident timeline was stale after a task changed** [#38426](https://github.com/open-metadata/OpenMetadata/pull/38426): The activity timeline now shows the new status after you acknowledge, assign, or resolve from the Inbox task panel, without closing the panel.
- **Inbox workflow transitions skipped required fields** [#38445](https://github.com/open-metadata/OpenMetadata/pull/38445): The Inbox now opens a form for a transition with required fields. Bulk resolve in My Tasks skips those tasks instead of resolving them without input.

### 🔌 Connectors and Ingestion

This release includes the following connector and ingestion improvements:

- **Adding a dbt data model removed a table's schema definition** [#38544](https://github.com/open-metadata/OpenMetadata/pull/38544): A table keeps its `schemaDefinition` when dbt ingestion adds a data model, and the next ingestion run restores one that was already lost.
- **MicroStrategy metrics of schema cubes had no column lineage** [#38337](https://github.com/open-metadata/OpenMetadata/pull/38337): Metrics now get column-level lineage through the SQL projection that matches their alias or name, or through the metrics and facts they are built from. Reading this lineage needs Architect read access.
- **Airflow administrators were denied access to pipeline services** [#38460](https://github.com/open-metadata/OpenMetadata/pull/38460): Helm deployments that use `FabAuthManager` no longer return 403 errors on the `health-auth` and `deploy` routes, because `can_create` is now authorized as `PUT`.

### ⚙️ Platform and Operations

This release includes the following platform and operations fixes:

- **A disabled alert reported pending events that would never be sent** [#38555](https://github.com/open-metadata/OpenMetadata/pull/38555), [#38588](https://github.com/open-metadata/OpenMetadata/pull/38588): A disabled alert now reports nothing pending and shows that it is disabled and not running.
- **Hard delete failed on MySQL with `Illegal mix of collations`** [#38444](https://github.com/open-metadata/OpenMetadata/pull/38444): Hard delete of a taggable entity no longer returns a 500 error on MySQL servers whose tables use different collations.
- **Push feed connections did not follow a sign-in provider change** [#38587](https://github.com/open-metadata/OpenMetadata/pull/38587): Push feed connections now close when the sign-in provider changes.

### 🎛️ User Interface (UI)

This release includes the following UI improvements:

- **The asset header did not show when an asset was last updated at its source** [#38276](https://github.com/open-metadata/OpenMetadata/pull/38276): The header now shows **Updated at source** as relative time, and created time no longer carries a UTC offset.
- **Cursor-paginated lists fetched twice and showed wrong pages** [#38472](https://github.com/open-metadata/OpenMetadata/pull/38472), [#38504](https://github.com/open-metadata/OpenMetadata/pull/38504): Lists now use one URL-driven fetch, and the Data Models and Stored Procedures page count no longer includes an extra empty page.
- **Knowledge Center version history showed a half-loaded page** [#38508](https://github.com/open-metadata/OpenMetadata/pull/38508): The version list and the version content now load separately, so you no longer see a blank content area or an empty timeline.
- **Table custom properties were capped at a fixed number of columns** [#38546](https://github.com/open-metadata/OpenMetadata/pull/38546): Table values now show three columns at a time with horizontal scroll.
- **Browse Estate collapsed after you removed a browse chip** [#38502](https://github.com/open-metadata/OpenMetadata/pull/38502): Removing a browse chip now keeps the tree expanded to the remaining path.
- **Platform Settings had no dark-mode logo option** [#38502](https://github.com/open-metadata/OpenMetadata/pull/38502): Platform Settings now accepts dark-mode logo and monogram URLs.
