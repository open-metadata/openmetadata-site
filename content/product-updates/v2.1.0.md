You can find the GitHub release [here](https://github.com/open-metadata/OpenMetadata/releases/tag/2.1.0-release).

OpenMetadata 2.1 adds richer Data Quality and governance, a larger Context Center, change requests for reviewing governance changes before they apply, and a complete Metrics entity. It also adds Ontology Explorer and a knowledge graph for your business vocabulary, seven new connectors, and many improvements to existing ones.

## Features

The following sections describe what is new in this release.

### Data Quality

This release gives you more control over how tests fail and clearer insight into test runs.

- **Failure thresholds**: Decide how much failure a test tolerates before it fails. Set the threshold as a number of rows or as a percentage. Percentages must be between 0 and 100.
- **Data Quality Dimensions**: Group your tests by dimension, such as completeness or accuracy, to see data quality from the angle your team cares about.
- **Filter by more than one status**: In the Test Cases tab and in the API, filter test cases by several statuses at once, such as Failed and Aborted.
- **Clearer run history**: The result history card shows a date range and summary tiles for your runs. Each result now records how long the run took and any error. A new run-details card shows why a run aborted.
- **Incident Manager**: A new Grouped Incidents view puts related incidents together. The Open card now counts incidents that are acknowledged or assigned, and the cards are labeled as daily counts.

### Governance

These changes give you more control over workflows, policies, and how governed assets are organized.

- **Smarter workflows**: A workflow condition can check how many assets or output ports a Data Product has. A workflow can also start when a column's custom property changes.
- **Governance by service**: Tags on a service now apply to its databases, schemas, and tables. Policy conditions can use an asset's service, for example to hide every asset from one service.
- **Impersonation in policies**: New `isImpersonated()` and `impersonatedBy()` conditions let a policy react when a user is acting on behalf of someone else.
- **Lifecycle stages**: Define lifecycle stages for your entities.
- **Domain styles**: Give each domain its own color and icon.
- **Glossary settings**: New glossary settings, including management of relation types.
- **Data Retention**: A new `workflowRetentionPeriod` setting lets the Data Retention app clean up old automation workflows.

### Context Center

Context Center now makes it easier to find, preview, and share content.

- **Articles toolbar**: Filter and sort articles from a new toolbar.
- **File preview**: Open Markdown, text, PDF, and image files without leaving OpenMetadata.
- **File visibility**: Control who can see a file.
- **Tabular profiles**: See tabular profiles on assets.
- **Query runner**: Attach files to query runner requests.
- **Linked articles**: Link Context Center articles from entity pages.

### Change Requests

Change requests let you review governance changes before they are applied, instead of changing the catalog directly.

- Reviewers see a preview of exactly what will change, then approve or reject it.
- The person who raised a request can withdraw it.
- Admins can override a request when needed.
- Workflow runs now show how each approval was decided, so you can see who approved a change and why.

### Metrics

Metrics are now a complete, browsable part of your catalog.

- **Hierarchy and details**: See a metric's full hierarchy and a detail page with Dimensions and Measures on the overview and an Assets tab that lists the assets it relates to.
- **Metric Groups**: Organize related metrics together in a new Metric Group.
- **Column-level links**: Link a metric to a specific table column, not just the table. Column-level lineage between them is kept.
- **Keeps your edits**: When ingestion updates a metric, its hierarchy, reviewers, and experts are no longer lost.
- **More sources**: Unity Catalog metric views and Looker measures are now ingested as Metrics.

### Lineage

Hierarchical lineage maps let you start from a high-level view and drill down from service to database, schema, asset, and column. Large lineage graphs load one section at a time, and breadcrumbs always show where you are.

### Alerts

Alerts are easier to set up and to monitor.

- **Alert health**: See whether an alert and its destinations are working.
- **Available options**: When you set up an alert, see which sources and conditions you can use.
- **Safer webhook secrets**: Webhook secrets are now encrypted with the server's Fernet key, the same way other secrets already are.

### Conversations and Announcements

Conversations have been rebuilt. They now support replies and filters, and each conversation records where it came from. Announcements now have a type, either Information, Warning, or Issue, so readers can quickly see how important an announcement is.

### Ontology Explorer and Knowledge Graph

Ontology Explorer is a read-only graph of your glossary terms and how they relate to each other. It is a Beta feature. The ontology APIs and the knowledge graph are also included in this release.

- **Explore your vocabulary**: See the terms and relations of every glossary in one graph, search for concepts, and switch between the Model and Data layers.
- **Ontology APIs**: Manage ontologies, concepts, properties, relationships, constraints, mappings, and releases, and run SPARQL Protocol and RDF Query Language (SPARQL) queries over an ontology's draft or active release.
- **Ontology Library and relationship types**: Install ready-made ontology packs, import and export ontologies, and manage relationship types.
- **Knowledge graph**: Turn on Resource Description Framework (RDF), which is off by default, to mirror every entity in your catalog into a triple store. This adds the Knowledge Graph tab, the SPARQL Playground, inference, validation, and the knowledge graph tools for AI agents.

### New Connectors

This release adds seven connectors.

- **Rill** (dashboard): Ingests Rill dashboards and their data models.
- **NATS JetStream** (messaging): Discovers streams and subjects, extracts schemas, and samples messages. Supports Basic, token, NKey, Transport Layer Security (TLS), and anonymous authentication.
- **ClickZetta** (database): Ingests metadata, usage and query lineage, and supports profiling, data quality, data diff, and dbt.
- **Salesforce Data360** (database and pipeline): Ingests Salesforce Data360 (formerly Data Cloud) as a database source and as a pipeline source.
- **Tableau** (pipeline): Ingests Tableau Prep flows and extract refreshes as pipelines.
- **Databend** (database): Ingests databases, tables, views, columns, and comments.
- **Neo4j** (database): Ingests graph node labels and relationship types as tables.

### Connector Improvements

These existing connectors and ingestion features have new options.

- **Microsoft Fabric**: Sign in with a certificate or a client secret.
- **SSH File Transfer Protocol (SFTP)**: Sign in with a username and password or with a key.
- **Druid**: Connect to brokers secured with TLS by using the `druid+https` scheme.
- **Hive**: Partition key columns are now marked in the metadata, so you can tell them apart from other columns.
- **Dagster**: Run status checks now honor the `statusLookbackDays` setting, which controls how many days back OpenMetadata checks run statuses.
- **dbt**: Assets are added to Data Products automatically when the dbt manifest sets `meta.openmetadata.dataProducts`.
- **Data contracts**: Importing an Open Data Contract Standard (ODCS) data contract now gives you an import report.
- **Run for a single asset**: Run an ingestion pipeline for one asset instead of the whole service.
- **Ingestion pipelines**: Set owners on a pipeline. Admins can force delete a pipeline when its runner is unavailable.

### Settings and Sign-in

These changes help you configure and test your deployment.

- **Test your login**: Test a single sign-on setup without signing out.
- **Where a setting comes from**: Settings show whether a value comes from the configuration file or from the UI.
- **Content delivery network (CDN)**: A new setting lets you serve UI assets from a CDN.
- **Applications**: The whole application card is clickable in **Settings** > **Applications**.

### API

The following API changes are included in this release.

- `GET /v1/services/overview` returns the number of services for each type, plus one sorted page of services, in a single call.
- New endpoints are available for ontologies, change requests, Metric Groups, Data Quality Dimensions, conversations, and RDF and SPARQL queries.
- The Model Context Protocol (MCP) `get_entity_lineage` tool supports column-level lineage and cursor paging.

## Breaking Changes

Take a full database backup before you upgrade. The 2.1.0 migration renames `thread_entity_legacy` to `thread_entity_archived`, creates new tables, rewrites task, lineage, alert, and application rows, and changes the MySQL default collation. To roll back, restore the backup.

### Collaboration

- **Feed API removed**: The `/v1/feed` API no longer exists. Use `/v1/conversations`, `/v1/tasks`, `/v1/activity`, and `/v1/announcements` instead.
- **Task threads are not migrated**: Task threads created through the feed API on 2.0.x stay in `thread_entity_archived`.
- **Alert event types removed**: Task and suggestion event types are no longer available in alerts.

### Ingestion and Connectors

- **Delta Lake connector removed**: Delta Lake services become Custom Database services, and their ingestion pipelines are deleted.
- **Pipeline `sourceConfig` type required**: Ingestion pipelines created through the API must set `sourceConfig.config.type`.
- **Microsoft Fabric authentication**: Move the client secret under the required `authType` field.

### Lineage

- **Lineage edges**: An edge can only name a pipeline or a stored procedure, and lineage reads now check permissions.
- **OpenLineage endpoint**: The endpoint reports datasets it cannot resolve and creates only tables automatically.

### Data Governance

- **Glossary relation type usage**: `GET /v1/glossaryTerms/relationTypes/usage` returns a list instead of a map.
- **RDF reasoning**: In-process Resource Description Framework (RDF) reasoning is removed, and the old inference settings are ignored.
- **Fuseki RDF store**: The bundled Fuseki store uses a new image, new settings, and a new data volume.
- **Glossary terms**: The API applies only Approved glossary terms to assets, and dbt ingestion skips terms that are not Approved.

### Data Quality

- **Test case validation**: New test cases are checked against their test definition.
- **Sample data storage**: `sampleDataStorageConfig` is removed from connection and profiler schemas.

### Applications and API

- **Alerts from applications**: Applications no longer create alerts from their definition, and existing definition-created alerts are disabled.
- **Admin-only actions**: Only admins can add roles or policies to a team, and creating an application with a bot needs an admin.
- **Removed schemas**: Several schema files and Java classes are removed, including `WorkflowTriggerFields`.

### Platform and Security

- **OpenID Connect (OIDC) sign-in**: Sign-in now returns the provider's ID token to the browser instead of an OpenMetadata token.
- **Email-first identity**: This is opt-in. User emails are lowercased on upgrade.
- **Search**: Search needs a reindex, and some search endpoints are now admin only.
- **Server image**: The server image runs on a distroless Debian base as user `65532`, with no package manager.
- **UI**: Ant Design is removed, which affects UI forks and plugins. The Add Metric routes are gone.

### Deprecations

The following items are deprecated in OpenMetadata 2.1. Move to the replacement soon.

- **Airflow as the internal orchestrator**: Replace with the native Kubernetes Orchestrator. Still works in 2.1. It will be removed in a future release.
- **Classic mode of the interface**: Replace with AI mode. Still works in 2.1. It will be removed in a future release.
- **`jwtPrincipalClaims`**: Replace with `emailClaim`. Still works in 2.1.
- **`jwtPrincipalClaimsMapping`**: Replace with `emailClaim` and `displayNameClaim`. Still works in 2.1.
- **`adminPrincipals`**: Replace with `adminEmails`. Still works in 2.1.
- **`principalDomain`**: Replace with `botDomain` for bots and `allowedEmailDomains` for user restrictions. Still works in 2.1.
- **`allowedDomains` and `enforcePrincipalDomain`**: Replace with `allowedEmailDomains`. Still works in 2.1.
- **`enableSecureSocketConnection`**: Nothing. The setting has no effect, because socket connections are always authenticated. No effect in 2.1.
- **The `/{alertType}/resources` alert endpoint**: Replace with `POST /capabilities`. Still works in 2.1.

For more information, see [Breaking Changes: 2.0 to 2.1](https://docs.open-metadata.org/v2.1.x-SNAPSHOT/deployment/upgrade/breaking-changes/overview).

## Changelog

### Connectors and Ingestion

- dbt Cloud ingestion now reads artifacts from multiple jobs and from every run step.
- dbt ingestion respects source physical identifiers, and `catalogMapping` now maps dbt manifest databases to OpenMetadata databases, including column lineage for those models.
- Added Sigma Data Model ingestion, links Sigma columns to the warehouse columns they show, and lists workbooks across the whole organization.
- Looker ingestion applies LookML view refinements.
- Unity Catalog lineage now resolves upstream tables across services.
- Kafka ingestion now collects sample data for Protobuf topics.
- StarRocks and Doris ingest STRUCT and ARRAY child columns, and StarRocks now ingests table comments.
- MySQL and MariaDB ingest views even when the user has no SELECT permission on them.
- CockroachDB ingests materialized views and filters schema comments correctly.
- Athena keeps Iceberg column types and warns about Hive views. It also recognizes partitioned Delta tables.
- SQL Server keeps CLR stored procedures in the catalog, and captures lineage from procedures that run `ALTER TABLE ... SWITCH`.
- Tableau ingestion now stops instead of deleting data models when the Metadata API backfill fails.
- Airflow ingestion checks only the latest pipeline runs for status.
- Google Cloud Storage-backed connectors now honor `gcpImpersonateServiceAccount`.
- Database connectors now have default filters for system schemas.
- MySQL connections now verify `sslConfig` certificates and reject an invalid `sslConfig`.
- Redshift now explains why an SSL connection was rejected.
- Fivetran ingestion reads the Platform Connector log from the account's own schema.
- Oracle table diff sampling now compiles with supported SQL, and Oracle view definitions are cached for faster ingestion.
- Vertica ingestion fetches column comments in bulk.

### Lineage

- Show or hide temporary tables between two tables in lineage.
- Edit lineage inline from node and column menus.
- The lineage tab stays responsive with very large lineage responses.
- Requests for a lineage root that does not exist now return a 404 error.
- OpenLineage `kafka://` datasets now resolve to topics.
- Trino cross-database lineage uses the correct schema name.
- Fixed a crash when dragging a lineage node to the edge of the canvas.

### Data Quality and Profiler

- Incidents of deleted test cases no longer appear in Incident Manager, and incident history is cleaned up when test cases are deleted.
- Test cases can be soft deleted and restored in AI mode, with a Deleted badge on the test case page.
- You can attach test cases to nested columns.
- The Test Cases tab shows the Last Run filter by default, and Export and Bulk Edit now apply only to the test cases you have filtered.
- Result messages for failure thresholds are clearer.
- Creating a test case pipeline is now optional.
- Fixed Teradata profiler crashes, and the profiler now works on tables with nested array columns.
- Profiler regex filters are now case-insensitive on both the server and the client.

### Governance and Workflows

- **Notify Downstream** alerts now reach the owners of downstream assets.
- Approval tasks show counted votes, and Approve is available only to assignees.
- Fixed Column Tags workflow conditions that always evaluated to false, and Tier conditions now evaluate against an entity's tags.
- A workflow run now ends when one branch of its fork fails, and approvals no longer start for updates that change nothing.
- Creating a workflow now asks for a display name. The name is derived from it and is read-only.
- Resolving a tag update now removes the tags it leaves out.
- Tag and classification drawers stay open when a save fails.
- Domain and data product chips use the color and icon from the domain styles.
- Data product domain validation now handles inherited domains.
- Editing classification tags on a data product in the Explore panel no longer deletes its glossary tags.
- Metric detail pages show and let you edit reviewers. Restoring a metric under a deleted parent is rejected.

### Alerts and Notifications

- You can edit an alert while a webhook secret is waiting to be entered again.
- Destination endpoints, header values, and credentials are stored encrypted and masked, and can be restored.
- Alerts on tasks now reach the task creator and the asset owners.
- Alert forms in AI mode accept several sources.
- Announcements appear in a banner on the Data Marketplace overview.
- Inbox marks Activity as seen only after the feed loads.

### Search

- Search stays in sync after updates, renames, label changes, and direct writes.
- Explore loads entity type counts faster.
- Search requests retry on OpenSearch `already_closed_exception` errors and on version conflicts.
- Added a Korean (KO) search index mapping with the nori analyzer.
- A reindex now refreshes embeddings whose text changed.
- A search against an index OpenMetadata does not manage returns a 400 error.
- Sample data in search indexes is masked when fields are marked PII.Sensitive.

### Authentication and Security

- The SAML configuration check is now signed and shows the identity provider's error reason.
- Bot tokens can be regenerated after a JSON Web Token (JWT) signing key change.
- The confidential OpenID Connect (OIDC) callback now requires an authorization code, and server-side OIDC sign-in syncs the user's display name and picture.
- A password reset now lifts a login lockout.
- Login request bodies are size limited, and the MCP server limits request body size.
- The MCP server can run under a non-root `BASE_PATH` and masks service connections in its responses.
- Authorization is now enforced on sub-resource, listing, and admin endpoints, as part of several batches of backend security hardening.
- Apache Tika and image OCR were removed from Context Center.
- Updated dependencies, including undici, fast-uri, and serialize-javascript.
