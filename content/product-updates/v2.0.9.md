## Changelog

OpenMetadata 2.0.9 is a maintenance release that improves connector reliability and lineage coverage, with updates for MicroStrategy and Sigma. It strengthens Data Quality, governance, and access control behavior. It also improves Model Context Protocol (MCP) handling, alerts, and user interface (UI) reliability. Security updates cover secrets masking, ingestion dependencies, document authorization, frontend libraries, and the Java runtime.

### 🔌 Connectors and Ingestion

This release includes the following connector and ingestion improvements:

- **MicroStrategy ingestion was unreliable and repeated work** [#37730](https://github.com/open-metadata/OpenMetadata/pull/37730), [#37855](https://github.com/open-metadata/OpenMetadata/pull/37855): The connector now skips documents it cannot read, parses cube SQL once, and routes lineage by project.
- **MicroStrategy lineage was missing for cubes and report datasets** [#37945](https://github.com/open-metadata/OpenMetadata/pull/37945), [#37980](https://github.com/open-metadata/OpenMetadata/pull/37980), [#38217](https://github.com/open-metadata/OpenMetadata/pull/38217): Column-level lineage now links cube SQL to data models, and a report built on an Intelligent Cube gets the cube's lineage. Warehouse reports, prompted reports, and Live cubes now log a clear reason when they have no lineage.
- **Sigma lineage was incomplete** [#37766](https://github.com/open-metadata/OpenMetadata/pull/37766): Element lineage now links only the tables a workbook element reaches. An optional `listAllAssets` setting lists assets across the whole organization, and data models gain upstream lineage and formula-based column lineage.
- **dbt applied glossary terms regardless of approval status** [#37719](https://github.com/open-metadata/OpenMetadata/pull/37719): Ingestion now applies a glossary term from `meta.openmetadata.glossary` only when its status is Approved. Terms in other statuses are skipped with a warning.
- **Profiler SQL changed literal SQL Server and Azure SQL schema names** [#37789](https://github.com/open-metadata/OpenMetadata/pull/37789): Literal schema names are now quoted and preserved in profiler queries.
- **Google Cloud Storage (GCS) child containers carried bucket-level metrics** [#37968](https://github.com/open-metadata/OpenMetadata/pull/37968): Structured child containers no longer report metrics that belong to the bucket.
- **Oracle percentage sampling read all rows or none** [#37940](https://github.com/open-metadata/OpenMetadata/pull/37940): A new Oracle sampler keeps percentage samples per row.
- **The datalake sampler dropped partially null rows and flattened list cells** [#38175](https://github.com/open-metadata/OpenMetadata/pull/38175): The sampler now keeps rows with some null values and returns list cells as lists.
- **BigQuery concurrent datasets could share data definition language (DDL) cache entries** [#38234](https://github.com/open-metadata/OpenMetadata/pull/38234): The DDL cache is now keyed by fully qualified name, so concurrent datasets stay separate.
- **Operation metrics could be recorded into the wrong run or miss an item** [#37899](https://github.com/open-metadata/OpenMetadata/pull/37899), [#38130](https://github.com/open-metadata/OpenMetadata/pull/38130): A summary now waits for the item the metrics worker already took. A new run drops stale items instead of recording them after the reset.
- **CSV imports could lose rows and entity versions** [#38192](https://github.com/open-metadata/OpenMetadata/pull/38192): An import that updates an existing entity now stores the version it replaces. Version history no longer skips or overwrites versions.

### 📊 Data Quality and Data Insights

This release includes the following Data Quality and Data Insights fixes:

- **Data Quality totals could miss table documents** [#37913](https://github.com/open-metadata/OpenMetadata/pull/37913): Summary and Test Cases totals now use an exact document count. Decimal-form aggregation counts also parse correctly.
- **Data Insights categorical axes listed categories their chart did not count** [#37898](https://github.com/open-metadata/OpenMetadata/pull/37898): A breakdown scoped to tables no longer lists categories held by other asset types at 0.
- **Incident Manager summary cards did not match the incident list** [#38222](https://github.com/open-metadata/OpenMetadata/pull/38222): The Open Incidents card now counts New, Acknowledged, and Assigned events. All four incident cards explain that they show daily activity, not a running total.

### 🛡️ Data Governance and Workflows

This release includes the following governance and workflow fixes:

- **Approved tag update tasks ignored removed tags** [#37724](https://github.com/open-metadata/OpenMetadata/pull/37724): Approving a tag update now removes the tags the task dropped. A replacement inside a mutually exclusive classification no longer leaves the column unchanged.
- **Tag recognizers could be saved without a supported language** [#37568](https://github.com/open-metadata/OpenMetadata/pull/37568): The server now rejects them.
- **Tag suggestion tasks showed raw JSON under Suggested Description** [#38114](https://github.com/open-metadata/OpenMetadata/pull/38114): The task view and the table's Suggested Tags view now show suggested tags as chips.
- **Metrics with most statuses showed the Draft badge** [#38009](https://github.com/open-metadata/OpenMetadata/pull/38009): Rejected, Unprocessed, Deprecated, and Archived metrics now show their real status. The status filter offers all of them.
- **A hard delete removed tags from entities that share its name** [#38230](https://github.com/open-metadata/OpenMetadata/pull/38230): Hard deletion no longer removes tags and field relationships from entities of another type with the same fully qualified name.
- **An undone edit hung approval workflows** [#38225](https://github.com/open-metadata/OpenMetadata/pull/38225): An update whose edit was undone no longer opens an approval task that never finishes. Renaming a tag whose name contains a backslash now evicts its cache entry.

### 🔗 AI Context and MCP Server

This release includes the following MCP improvements:

- **Disabling the MCP Server app did not stop MCP** [#37727](https://github.com/open-metadata/OpenMetadata/pull/37727): MCP routes now stop without a server restart.
- **`get_entity_details` without `entityType` returned a server error** [#38160](https://github.com/open-metadata/OpenMetadata/pull/38160): The MCP tool now rejects the request as a 400 instead of throwing a null pointer error.

### 🔍 Search and Discovery

This release includes the following search fixes:

- **The orphan sweep could fail a reindex job that was still initializing** [#38120](https://github.com/open-metadata/OpenMetadata/pull/38120): Reindex jobs are no longer failed while their partitions are being built.

### 🔐 Authentication and Access Control

This release includes the following authentication and access control fixes:

- **A disabled policy or removed rule could keep granting access** [#37996](https://github.com/open-metadata/OpenMetadata/pull/37996): The per-user policy cache is now cleared when a policy's enabled flag changes. The next authorization decision reflects the change.
- **A custom role named `Admin` duplicated the administrator option** [#38121](https://github.com/open-metadata/OpenMetadata/pull/38121): The server now rejects a new role named `Admin` in any letter case. Existing roles keep working, and role editors label the admin flag apart from roles.
- **Okta Security Assertion Markup Language (SAML) certificates whose common name is the organization name were rejected** [#33625](https://github.com/open-metadata/OpenMetadata/pull/33625): These certificates are now accepted.
- **Signup and password-reset email failures caused a server error** [#38232](https://github.com/open-metadata/OpenMetadata/pull/38232): The `424` failed-send status is now returned to the caller.

### 📣 Alerts and Events

This release includes the following alert and event fixes:

- **Opening an alert page could run the server out of memory** [#38094](https://github.com/open-metadata/OpenMetadata/pull/38094): The pending count no longer loads every change event after the alert's position in one query.
- **Task-created notifications linked to a page that does not exist** [#38090](https://github.com/open-metadata/OpenMetadata/pull/38090): A dedicated template now links to the task and the asset. It also lists the proposed changes.

### ⚙️ Platform and Operations

This release includes the following platform and operations fixes:

- **The audit log cleanup in the 2.0.8 upgrade could run for hours on large audit logs** [#38153](https://github.com/open-metadata/OpenMetadata/pull/38153): An entity-type index is now added before the cleanup runs.
- **Lifecycle-only updates replaced the version author** [#37995](https://github.com/open-metadata/OpenMetadata/pull/37995): A lifecycle patch no longer saves the usage bot as the current version's `updatedBy` and `updatedAt`. Column descriptions are no longer credited to the wrong user.
- **The bundled MySQL image used an unpinned MySQL 8.0 base** [#38172](https://github.com/open-metadata/OpenMetadata/pull/38172): Docker images and test defaults now use MySQL `8.4.13`. MySQL 8.0 ingestion sources remain supported.

### 🎛️ UI

This release includes the following UI fixes:

- **The My Tasks widget slowed the My Data page** [#37944](https://github.com/open-metadata/OpenMetadata/pull/37944): Task cards now mount only when they scroll into view.
- **Composite unique constraints looked the same as single-column ones** [#38178](https://github.com/open-metadata/OpenMetadata/pull/38178): The schema table and the table version history now distinguish them.
- **Testing a connection from the service page ignored the service's runner** [#38159](https://github.com/open-metadata/OpenMetadata/pull/38159): The test request now sends the runner configured on the service.

### 🔒 Security

This release includes the following security updates:

- **Secrets nested in a schema `oneOf` appeared in plain text** [#37962](https://github.com/open-metadata/OpenMetadata/pull/37962), [#38184](https://github.com/open-metadata/OpenMetadata/pull/38184): Secrets such as the Databricks Pipeline `token` and `clientSecret` are now masked and encrypted. The 2.0.9 migration also masks plain text secrets left in service version history.
- **Ingestion dependencies had known vulnerabilities, and Power BI `.pbit` extraction was unsafe** [#37861](https://github.com/open-metadata/OpenMetadata/pull/37861): Dependency floors rise for `oauthlib`, `filelock`, `dnspython`, `tornado`, and OpenTelemetry. Power BI extraction now skips archive members whose path escapes the extraction directory.
- **Document Store email template writes were authorized in several places** [#38204](https://github.com/open-metadata/OpenMetadata/pull/38204): One helper now requires an administrator on every write endpoint that changes email templates.
- **BlockEditor mention links could reach back to the opening page** [#38089](https://github.com/open-metadata/OpenMetadata/pull/38089): Links now open with `noopener` and `noreferrer`.
- **The core UI components depended on a vulnerable `minimatch`** [#38106](https://github.com/open-metadata/OpenMetadata/pull/38106): `minimatch` moves to 11.0.9 for GHSA-g3hv-75wg-m249.
- **The Java runtime lacked the November 2026 OpenJDK security release** [#38125](https://github.com/open-metadata/OpenMetadata/pull/38125): Images are now built on Amazon Corretto 21.0.13.1.2.
